# ScriptAgent 智稿引擎 需求文档

> 本文档定义 ScriptAgent 智稿引擎项目的功能需求和非功能需求，作为后续技术方案设计、研发实施、测试验收的依据。本文档回答 **What**，不回答 **How**，How 在后续的技术方案中展开。前置阅读《ScriptAgent 智稿引擎 行业调研》和《ScriptAgent 智稿引擎 - 完整系统架构设计文档（SDD版）》，本文档基于 SDD 的定位展开，不重复论证 AI 写作中台领域的现状。

---

## 1. 项目概述

### 1.1 ScriptAgent 是什么

ScriptAgent 智稿引擎是一款基于 AgentScope2.0 开发的**通用 AI 写作中台系统**，面向内部用户提供三类核心写作能力。它部署在组织内网，作为统一写作底座，让员工在一个工作台里完成日常大部分写作任务，素材、模板、稿件在系统内统一沉淀，用户数据完全隔离。

技术特征一句话：**SpringBoot3.x + Java21 单体应用，AgentScope2.0 做 Agent 底座，Redis 管会话、ES 管素材检索、MySQL 管业务数据，Agent 无状态、轻量易部署、适配 SDD 迭代开发。**

业界已有企业级写作平台把这套需求验证过（阿里云 AI 妙笔、腾讯云 WorkBuddy、WPS 365 等），但多为绑定云生态的重型 SaaS；轻量、私有、可快速迭代、用户级素材资产化的通用写作中台在 Java 生态仍是空白。ScriptAgent 填这个位置。

#### 核心设计四原则

1. **Agent 无状态**：写作 Agent 不持有任何状态，状态全部外置到 Redis/ES/MySQL，天然支持水平扩展。
2. **会话放 Redis**：多轮对话上下文、Token、限流都在 Redis，读写快、TTL 可控。
3. **素材检索放 ES**：素材切片向量入库 ES7，RAG 仿写走语义检索。
4. **用户数据完全隔离**：素材、会话、稿件、模板全部绑定 UserId，查询强制携带 user_id。

#### 交付分五段

SDD 定义了明确的开发优先级，按五阶段交付：

1. **基础底座**：Maven 多模块骨架、公共模块、JPA 基础配置、极简登录、Token 拦截器、Redis/ES 配置
2. **素材 RAG 底座**：文件解析、文本切片、ES 向量入库与检索、素材上传列表
3. **Agent 核心能力**：AgentScope 集成、Redis 会话记忆、ES 检索工具、三类写作 Agent
4. **前端业务页面**：登录页、三大写作 Tab 工作台、模板管理、稿件历史
5. **联调、优化、收尾**：流式输出、异常处理、数据隔离校验、BUG 修复

### 1.2 ScriptAgent 能干什么

ScriptAgent 优先做三类核心写作能力，加上四类支撑能力。三类核心写作能力是产品价值的本体，支撑能力让整个写作链路闭环。

#### 能力一：一句话多轮对话写作

用户用一句话描述写作需求，Agent 生成初稿，用户继续追问、修改、润色，多轮迭代直到满意。

**基于这个能力可以做的事：**
- 想写什么直接说："帮我写一份 618 大促的公众号推文大纲"
- 生成后继续迭代："开头再活泼一点""第二段补充产品卖点""压缩到 800 字"
- 自由写作场景全覆盖：文案、周报、邮件、通知、方案、总结

**技术要点**：无需 ES 检索；多轮上下文靠短期记忆（Redis 会话）承载，对话开始注入长期记忆（用户偏好）与核心记忆（Agent 身份/任务定义），SSE 流式输出，生成结果落稿件历史。

#### 能力二：素材文档仿写（RAG）

用户上传参考文档（PDF/Word/TXT/MD），系统自动解析、切片、向量入库；写作时按用户意图在 ES 中检索相似素材，注入提示词让 AI 参考素材的风格与事实产出文稿。

**基于这个能力可以做的事：**
- 上传历史标书，仿写出新项目的投标方案
- 上传竞品文案合集，仿写出风格一致的营销内容
- 上传内部制度文档，按规范格式重写通知、公告
- 素材库越用越厚，写作越来越有依据（缓解幻觉）

**技术要点**：POI + PDFBox 解析 → 固定长度 + 重叠切片 → Embedding 向量化 → ES7 批量入库 → 写作时按用户 ID 检索相似切片 → 参考素材 + 仿写 Prompt 调 LLM。

#### 能力三：固定模板写作

预设写作模板（结构 + 变量 + 规范说明），用户填参数，系统渲染模板并生成规范文稿。

**基于这个能力可以做的事：**
- 周报模板：填本周工作/下周计划，生成标准格式周报
- 会议纪要模板：填议题/结论/待办，生成规范纪要
- 公文模板：填标题/正文要点，生成格式合规的公文
- 组织把写作规范固化成模板，产出天然合规

**技术要点**：模板存 ES（模板库），前端动态表单填参，后端模板渲染 + Prompt 组装，结果落稿件历史。

#### 支撑能力

| 支撑能力 | 说明 |
|---------|------|
| 登录鉴权 | 极简登录（BCrypt + UUID Token + Redis），全局 Token 拦截器，未登录拦截 |
| 素材管理 | 素材上传、列表、预览、删除（删除同步清 ES 切片） |
| 模板管理 | 模板新增、编辑、启用停用、变量配置 |
| 稿件历史 | 所有写作记录、重新编辑、导出 Word、删除 |

#### 三个能力组合可以解决的场景

| 场景 | 对话写作 | 素材仿写 | 模板写作 |
|------|---------|---------|---------|
| 运营写公众号推文 | 一句话起稿、多轮润色 | 参考历史爆款文案风格 | 用推文模板快速出框架 |
| 售前写投标方案 | 自由组织方案框架 | 上传历史标书仿写 | 用方案模板填参数 |
| 行政写通知公告 | 自然语言起草 | 参考内部制度文档 | 用公文模板出规范格式 |
| 研发写技术文档 | 对话式梳理结构 | 参考接口文档/设计文档 | 用文档模板统一格式 |
| 全员写周报月报 | 说重点让 AI 扩写 | — | 用周报模板一键生成 |

## 2. 术语和概念

为避免歧义，统一核心术语定义：

| 术语 | 定义 |
|------|------|
| **Agent（写作智能体）** | 封装了 LLM 调用、工具调用、记忆管理的写作执行单元，由 Agent 工厂按写作模式生成，无状态 |
| **Agent 工厂** | 根据写作模式（对话/仿写/模板）生成不同配置的写作 Agent 的组件 |
| **素材（Material）** | 用户上传的参考文档（PDF/Word/TXT/MD），是 RAG 仿写的数据源 |
| **切片（Chunk）** | 长文档按固定长度 + 重叠切成的文本片段，向量化和检索的基本单元 |
| **Embedding（向量化）** | 把文本映射为向量，用于语义相似度检索 |
| **模板（Template）** | 预设的写作结构，含静态文本 + 变量占位符 + 规范说明，存 ES 模板库 |
| **稿件（Article）** | AI 生成的历史文稿，可查看、重新编辑、导出 Word |
| **RAG** | Retrieval-Augmented Generation，检索增强生成，生成前先从素材库检索相关片段注入提示词 |
| **会话（Session）** | 一次多轮对话的上下文，存 Redis，含对话历史、当前上下文 |
| **SSE** | Server-Sent Events，服务器单向推送，AI 生成内容流式实时返回前端 |
| **Token** | 登录凭证，登录成功签发 UUID Token 存 Redis（Token→UserId），后续请求携带鉴权 |
| **UserContext** | 拦截器解析 Token 后存入的当前用户上下文，实现全局用户隔离 |
| **ESRetrieveTool** | AgentScope 自定义工具，封装 ES 素材向量检索，供 Agent 调用 |
| **RedisMemory** | AgentScope 自定义会话记忆实现，底层对接 Redis，承载**短期记忆** |
| **短期记忆（会话记忆）** | 当前一次多轮对话的完整历史，存 Redis，TTL 过期，超长触发压缩 |
| **长期记忆（用户偏好记忆）** | 跨会话的用户写作偏好、风格、常用术语，存 MySQL `writing_memory` 表，每次对话注入 |
| **核心记忆（Agent 身份与任务定义）** | Agent 固定不变的"人格 + 干什么"：三类写作 Agent 的系统指令、Prompt 骨架、约束，固定注入 system prompt，不被压缩清除 |
| **上下文压缩（AutoContextMemory）** | 对话历史超过上下文窗口阈值时，用 LLM 把早期对话蒸馏成摘要，保留最近几轮；压缩前先抽取长期记忆 |
| **AgentScope** | 阿里开源的多智能体应用框架，提供 Agent 管理、工具调用、记忆管理（短期 MemoryBase / 长期 LongTermMemoryBase / 上下文压缩 AutoContextMemory）能力 |

## 3. 设计目标

ScriptAgent 的核心目标可以用四个词概括：**轻量、复用、隔离、可迭代**。

| 目标 | 说明 |
|------|------|
| **轻量** | 单体应用、7 个 Maven 模块、一条命令打包运行，Redis/ES/MySQL 都是成熟组件，部署成本低 |
| **复用** | 一套 Agent 底座支撑三种写作模式，一套存储支撑所有写作场景，能力不重复建设 |
| **隔离** | 用户数据完全隔离，Token 鉴权 + 查询强制 user_id，任何人只能访问自己的素材、会话、稿件、模板 |
| **可迭代** | 模块单向依赖、无循环依赖，适配团队 SDD 迭代开发，每阶段有可交付成果 |

## 4. 典型场景

以下三个典型场景描述 ScriptAgent 完整形态下的目标用法。

### 场景一：运营写公众号推文（一句话多轮对话写作）

某互联网公司市场运营小王，接到任务写一篇新品上市的公众号推文。他打开写作工作台的"一句话多轮写作"Tab，输入"帮我写一篇新品智能音箱上市的公众号推文，主打音质和性价比"。Agent 秒级生成初稿，小王继续迭代："开头加一个场景化的痛点引入""卖点部分重点讲音质，突出对比行业旗舰""结尾加行动号召，控制在 1000 字"。几轮对话后，一篇符合预期的推文就绪，小王点击保存，稿件进入历史列表。

**ScriptAgent 在此场景的角色**：对话写作 Agent、Redis 会话记忆（多轮上下文）、SSE 流式输出、稿件历史落库。

### 场景二：售前写投标方案（素材文档仿写 RAG）

某软件公司的售前工程师老张，需要为一新项目写投标方案。他手里有一份上季度同类项目的投标方案 PDF 和一份客户需求文档。老张把两份文档上传到素材库，打开"素材仿写写作"Tab，输入"参考我的素材，写一份本次项目的技术方案章节，突出我们的实施经验"。系统检索到素材中相关的历史方案片段，结合仿写 Prompt 生成初稿，风格和术语与历史方案一致，事实有据可依。

**关键点**：素材归属用户、按用户检索（不会检索到别人的素材）；切片 + 向量检索保证召回的是最相关的片段；生成结果可追溯到参考素材。

### 场景三：全员写周报（固定模板写作）

某公司行政部在模板库配置了"周报模板"：本周工作（多行输入）、下周计划（多行输入）、风险与求助（可选）。员工在"模板写作"Tab 选择周报模板，动态表单填参数，一键生成规范格式的周报，直接复制到邮件或 OA。组织层面的写作规范被固化在模板里，新员工不需要学习格式，产出天然合规。

**ScriptAgent 在此场景的核心能力**：模板库（ES 存储）、动态表单、模板渲染 + Prompt 组装、稿件落库。

## 5. 核心功能

> 核心功能是 SDD 五阶段内必须完成的完整链路，对应"三类写作能力 + 四类支撑能力"。目标是跑通一个完整闭环：登录 → 进工作台 → 用三种方式写作 → 素材/模板可管理 → 稿件可沉淀。

### 5.1 登录鉴权（极简版）

- 账号密码登录，密码 BCrypt 加密存储（不引入 SpringSecurity）
- 登录成功签发 UUID Token，存 Redis（Token→UserId），设置过期时间
- 前端本地存储 Token，后续请求 Header 携带 Token
- 全局 Token 拦截器校验 Token，解析出用户存入 UserContext，实现全局用户隔离
- 未登录请求一律拦截返回未授权

**账号体系**：单表用户（sys_user），初始手动插入 admin 用户，支持根据用户名查询。

### 5.2 一句话多轮对话写作

- 对话式输入框，用户自由描述写作需求
- SSE 流式输出，生成内容实时显示
- 多轮对话，支持反复修改、风格调整、篇幅控制
- 对话上下文存 Redis（**短期记忆**，RedisMemory），无需 ES 检索
- 对话开始注入**长期记忆**（用户写作偏好，MySQL writing_memory），AI 越用越懂用户
- 生成结果保存为稿件历史记录（可选自动保存）

### 5.3 素材上传与 RAG 入库

- 支持 pdf / docx / txt / md 四种格式
- 后端校验文件格式、大小
- 文档解析提取纯文本（POI + PDFBox）
- 文本智能切片：固定长度 + 重叠
- 调用 Embedding 模型生成向量
- 切片文本 + 向量批量写入 ES7（索引 writing_material_chunk，文档携带用户维度）
- JPA 写入 MySQL 素材主信息（writing_material），关联 UserId

### 5.4 素材仿写写作

- 用户选择自己的素材（或使用刚上传的素材）、输入仿写需求
- 后端按用户 ID 在 ES 检索相似切片内容（ESRetrieveTool）
- AgentScope 调用 ESRetrieveTool 获取参考素材
- 结合仿写 Prompt + 参考素材调用 LLM 生成文稿
- SSE 流式返回前端，同时存入 Redis 会话
- 生成完成，JPA 保存稿件历史记录

### 5.5 记忆能力（三层）

三类写作共享同一套三层记忆，与 AgentScope 的记忆机制（MemoryBase / LongTermMemoryBase / AutoContextMemory）对齐：

| 层 | 存什么 | 存哪里 | 说明 |
|----|--------|--------|------|
| **短期记忆** | 当前对话历史（**只存 user 输入 + assistant 最终回复**，丢弃推理/tool 中间态） | Redis（RedisMemory） | 每轮追加，**默认保留最近 10 轮**（可配置），TTL 过期，超长触发压缩 |
| **长期记忆** | 用户写作偏好、风格、术语 | MySQL `writing_memory` | 对话开始注入；Agent 用 `save_memory` 回写稳定偏好 |
| **核心记忆** | Agent 身份、任务定义、Prompt 骨架、约束 | 代码/配置（Prompt 管理） | 固定注入 system prompt，不被压缩清除 |

- **写入**：长期记忆由 Agent 识别到稳定偏好时主动调用 `save_memory` 写入，系统不自动抽取、不自作主张猜
- **注入**：核心记忆最前，长期记忆中量，短期记忆（最近 10 轮）最后，按序拼进 system prompt
- **短期记忆只存对话层消息**：Redis 中为 `[{role: user/assistant, content}...]`；Agent 思考过程、tool 调用与执行输出（如检索到的素材片段）一律不写入，本轮参考素材由业务编排在组装 Prompt 时重新注入
- **压缩**：短期记忆超长时，先用 LLM 蒸馏早期对话为摘要（压缩前先抽取长期记忆），保留最近几轮

### 5.6 模板写作

- 模板库（ES）提供可用模板列表
- 前端根据模板变量配置动态生成表单
- 用户填参数提交
- 后端读取模板配置、动态填充参数、组装 Prompt 生成规范文稿
- 结果通过 JPA 入库保存稿件

**模板是什么（详见技术方案第 7 章完整示例）**：一条模板 = "固定结构 + 可填变量 + 写作要求"三部分，存 ES 模板库。

- **structure（固定结构）**：模板正文骨架，含变量占位符 `如 ${title}`、`${week_work}`
- **variables（可填变量）**：每个变量的 key、label（表单文案）、type（text/textarea/select）、required、placeholder，前端据此自动生成表单
- **prompt（写作要求）**：可选的规范说明，注入生成时的 Prompt

示例字段（周报模板）：structure 定义"标题 / 本周工作 / 下周计划 / 风险与求助"四段结构，variables 定义四个对应输入框（标题为文本、其余为多行文本），用户在模板页填参数一键生成规范周报。

### 5.7 素材管理

- 素材上传（进入 5.3 入库流程）
- 素材列表（分页，仅当前用户）
- 素材预览（展示解析后的文本内容）
- 素材删除（删除 MySQL 主记录 + 同步清理 ES 切片数据）

### 5.8 模板管理

- 模板新增（配置结构、变量、规范说明）
- 模板编辑
- 模板启用 / 停用
- 模板变量配置（变量名、类型、提示文案）

### 5.9 稿件历史

- 所有写作记录列表（分页，仅当前用户）
- 稿件查看（内容展示）
- 重新编辑（把历史稿件作为对话上下文继续迭代）
- 导出 Word
- 删除记录

### 5.10 流式输出（SSE）

- 三类写作的生成过程均通过 SSE 流式返回
- 前端实时渲染增量内容，提升长文生成体验

## 7. 非功能需求

### 7.1 性能

| 指标 | 目标 |
|------|------|
| 登录接口 P95 延迟 | ≤ 200ms |
| 素材上传入库（10MB 内文档） | ≤ 30s（含解析、切片、向量化、ES 写入） |
| ES 素材检索 P95 延迟 | ≤ 300ms |
| 首 token 返回时间（LLM 生成） | ≤ 3s（取决于模型服务，中台侧不额外引入明显延迟） |
| 单用户并发会话数 | ≥ 5 个 |
| 稿件历史分页查询 P95 延迟 | ≤ 500ms |

（LLM 生成本身的总时长取决于模型服务，不在中台控制范围内）

### 7.2 可靠性

- 会话数据存 Redis 且有 TTL，掉线后按 Token 可恢复（Redis 可用性依赖组件保障）
- 素材入库失败时给出明确错误提示，不产生半成品数据（解析失败不回写 ES）
- LLM 调用失败时给用户可理解的错误信息，不静默失败
- 删除素材同步清 ES 切片，保证无孤儿数据

### 7.3 可运维性

- 单体应用，一条命令打包运行（`mvn clean package` → `java -jar`）
- 配置集中在 yml（数据源、Redis、ES、模型服务地址与 key）
- 开发环境 ddl-auto=update 自动建表，生产环境关闭自动建表、手动执行 SQL 脚本
- 启动、运行日志结构化，关键链路（登录、入库、写作）有日志

### 7.4 兼容性

- **JDK**：21（Spring Boot 3.x 要求）
- **数据库**：MySQL 8
- **Redis**：4.x 及以上（兼容常用版本）
- **ES**：7.x（兼容 7.x 主流版本）
- **浏览器**：Chrome / Edge 等现代浏览器（Vue3 前端）

### 7.5 安全

- 密码 BCrypt 加密存储，不存明文
- Token 存 Redis，可过期、可失效
- 全局拦截器校验，未登录拦截
- 查询强制携带 user_id（Service 层统一控制），防越权访问他人素材/稿件
- 文件上传校验格式与大小，防恶意文件
- 素材内容属于用户数据，接口按用户隔离返回

### 7.6 合规

- **数据驻留**：私有部署，数据不出内网
- 用户素材、稿件为个人数据，按用户隔离存储与访问
- 后续扩展：操作审计、数据导出、删除权（配合企业数据管理要求）

## 8. 关键流程

### 流程一：登录鉴权

```
用户输入账号密码登录
  → 后端 JPA 查询 MySQL sys_user 表（按用户名）
  → BCrypt 比对密码
  → 校验成功签发 UUID Token，存入 Redis（Token→UserId）
  → 前端保存 Token，后续请求 Header 携带
  → 拦截器校验 Token，解析出用户存入 UserContext，实现全局用户隔离
```

### 流程二：素材上传与 ES 入库（核心 RAG）

```
前端上传文件（pdf/docx/txt/md）
  → 后端校验文件格式、大小
  → POI + PDFBox 解析文档提取纯文本
  → 文本智能切片（固定长度 + 重叠）
  → 调用 Embedding 生成向量
  → 切片文本 + 向量批量写入 ES7（writing_material_chunk，携带用户维度）
  → JPA 写入 MySQL 素材主信息（writing_material，关联 UserId）
```

### 流程三：素材仿写（最高频 RAG 链路）

```
用户选择自己的素材、输入仿写需求
  → 后端根据用户 ID 在 ES 检索相似切片内容
  → AgentScope 调用 ESRetrieveTool 获取参考素材
  → 结合仿写 Prompt + 参考素材调用 LLM 生成文稿
  → SSE 流式返回前端，同时存入 Redis 会话
  → 生成完成，JPA 保存稿件历史记录
```

### 流程四：一句话多轮对话写作

```
用户输入一句话写作需求
  → 后端路由到对话写作 Agent
  → 注入核心记忆（Agent 身份与任务定义）+ 长期记忆（用户偏好，MySQL writing_memory）
  → 读取 Redis 会话记忆（短期记忆）作为多轮上下文
  → 组装对话写作 Prompt 调用 LLM
  → SSE 流式返回，多轮上下文持续写入 Redis 会话
  → 生成结果保存稿件历史记录
（无需 ES 检索；长对话超阈值时触发上下文压缩，压缩前先抽取长期记忆）
```

### 流程五：模板写作

```
用户选择模板、填参数提交
  → 后端读取 ES 模板配置
  → 动态填充用户参数
  → 组装模板写作 Prompt 生成规范文稿
  → 结果通过 JPA 入库保存稿件
```

## 9. 数据模型

### 9.1 sys_user 用户表（MySQL）

### 9.3 writing_article 稿件历史表（MySQL）

| 字段 | 类型 | 说明 |

跨会话用户偏好记忆（见 5.5 记忆能力），按用户隔离、查询强制 user_id。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，自增 |
| user_id | BIGINT | 归属用户，强制携带 |
| memory_type | VARCHAR | 记忆类型（style / term / habit / other） |
| content | TEXT | 记忆内容（一条用户偏好/事实） |
| source | VARCHAR | 来源（save_memory 工具 / 会话压缩抽取） |
| create_time | DATETIME | 创建时间（审计自动填充） |
| update_time | DATETIME | 更新时间 |
| deleted | TINYINT | 逻辑删除标记 |

### 9.5 ES 索引：writing_material_chunk

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR | 切片 ID |
| material_id | BIGINT | 关联素材 |
| user_id | BIGINT | 归属用户（检索强制带） |
| chunk_index | INT | 切片序号 |
| chunk_text | TEXT | 切片文本 |
| embedding | dense_vector | 向量（BGE bge-m3 生成，**dim=1024**，距离用 cosine） |

- 用途：RAG 仿写时按用户 + 语义检索相似切片
- 删除素材时按 material_id 同步清理

### 9.6 Redis key 设计

| Key | Value | 说明 |
|-----|-------|------|
| `token:{token}` | UserId | 登录 Token（Token→UserId），TTL 过期 |
| `session:{userId}:{sessionId}` | 对话层消息数组 JSON（只含 user 输入 + assistant 最终回复） | 多轮对话上下文（短期记忆，默认最近 10 轮） |
| `sse:cache:{userId}:{sessionId}` | 流式内容缓存 | SSE 流式缓存 |

## 11. 风险与未决事项

### 已识别风险

| 风险 | 描述 | 应对措施 |
|------|------|---------|
| **AgentScope 集成复杂度风险** | AgentScope2.0 功能丰富，与 Spring Boot 的集成方式需要摸索 | 第三阶段先跑通最小闭环（一个 Agent + 一个工具），再扩展三类写作 Agent |
| **文档解析质量风险** | 复杂 PDF（扫描件、复杂排版）解析效果不稳定 | 核心阶段支持文本型文档，扫描件 OCR 放扩展；解析失败给明确提示 |
| **向量检索效果风险** | 固定长度切片 + Embedding 检索的召回质量可能不稳定 | 切片参数（长度/重叠）可配置调优；扩展阶段引入混合检索和 ReRank |
| **SSE 长连接稳定性风险** | 流式输出在网络波动时可能中断 | SSE 缓存到 Redis，前端支持重连；扩展阶段优化断点续传 |
| **数据隔离被绕过的风险** | 开发过程中可能漏写 user_id 导致越权 | Service 层统一控制查询，禁止不带 user_id；第五阶段专项验证 |
| **ES 版本兼容风险** | ES7 与 Spring Data / 客户端版本组合需适配 | 锁定 ES7 兼容版本，用官方 Java Client / 对应 Spring Data 版本 |
| **范围膨胀风险** | 功能越加越多，五阶段完不成 | 核心功能范围卡紧，非核心需求进扩展功能清单 |

### 未决事项

| 事项 | 说明 | 决议时间 |
|------|------|---------|
| AgentScope 与 Spring Boot 的集成方式 | 直接使用 AgentScope 原生 API 还是其 Spring 适配 | 技术方案阶段 |
| 切片参数默认值 | 固定长度（如 512 字）与重叠（如 50）的默认取值 | 技术方案阶段 |
| ES 检索的相似度阈值 | 检索结果的相关性阈值与返回条数 | 技术方案阶段 |
| 稿件自动保存策略 | 对话写作是否每轮自动保存稿件 | 技术方案阶段 |

**已决议的模型选型**：LLM 采用阿里云百炼通义千问（Qwen，DashScope API）；向量化 Embedding 采用 **BGE bge-m3**（本地模型文件 + JVM 进程内 ONNX Runtime 推理，维度 1024）。详见技术方案第 9.3 节。备选：Embedding 走阿里百炼 text-embedding-v4（免本地模型、数据经阿里）。

## 13. 总结

ScriptAgent 智稿引擎是一款基于 AgentScope2.0 的通用 AI 写作中台，面向内部用户提供一句话多轮对话写作、素材文档仿写（RAG）、固定模板写作三类核心能力，配以登录鉴权、素材管理、模板管理、稿件历史四类支撑能力。

**核心设计四原则：**

- **Agent 无状态**：写作 Agent 不持有状态，状态全部外置，天然支持扩展
- **会话放 Redis**：多轮对话上下文、Token、限流统一在 Redis
- **素材检索放 ES**：素材切片向量入库，RAG 仿写走语义检索
- **用户数据完全隔离**：素材、会话、稿件、模板全部绑定用户，查询强制 user_id

**技术底座**：SpringBoot3.x + Java21 + Spring Data JPA + AgentScope2.0 + Redis4 + ES7 + MySQL8，前端 Vue3 + Element Plus + Pinia + SSE。

**交付分五段**：基础底座 → 素材 RAG 底座 → Agent 核心能力 → 前端业务页面 → 联调优化收尾，每阶段有可演示成果，适配团队 SDD 迭代开发。

**核心理念**：把"写东西"这件组织里的高频重复劳动，用三类写作形态统一承接；素材、模板、稿件在系统内沉淀复用；数据完全留在企业内网、按用户隔离。ScriptAgent 不绑定具体行业，组织按自己的写作场景组合使用。

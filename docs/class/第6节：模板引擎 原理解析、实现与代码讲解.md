# 第6节：模板引擎 原理解析、实现与代码讲解

模板引擎是 ScriptAgent 能力三"固定模板写作"的载体。这节讲四件事：模板引擎是什么、动手前该想清楚什么、代码怎么写、做完怎么验。核心是**结构 + 变量 + Prompt 三要素**，模板配置存 ES 模板库（§7）。

---

## 一、模板引擎是什么，干嘛用的

一句话：让用户选一个模板、填几个参数，系统就按模板的固定结构生成一篇规范文稿，不用每次从头写。

通俗例子：填报销单。表单（模板的 variables）是固定的几栏，你填内容（参数），系统按格式（structure）把内容填进去，生成一张规范的单子（文稿）。模板把"格式骨架"和"具体内容"分开，改内容不改格式、改格式不改内容。

在整套系统里，模板引擎 = **ES 模板库（存结构资产）+ 动态表单（前端）+ 渲染（后端）**，模板是结构资产、素材是内容资产，两者分离。

## 二、动手前先想清楚几件事

### 第一，模板的组成：structure + variables + prompt

一条模板就是一个 JSON 文档，三个核心字段缺一不可：

| 字段          | 作用                                                                                    |
| ------------- | --------------------------------------------------------------------------------------- |
| `structure` | 模板正文结构：静态文本 +`${变量名}` 占位符，给 LLM 的格式骨架                         |
| `variables` | 变量配置数组（key/label/type/required/placeholder/options），**驱动前端动态表单** |
| `prompt`    | 可选的额外写作要求/规范，注入 Prompt                                                    |

### 第二，为什么存 ES 模板库、为什么 variables 驱动表单

模板是结构资产，量大、要检索、要按用户隔离，放 ES 合适；素材是内容资产放 ES 素材索引，两者职责清晰。**variables 驱动表单**：前端根据 variables 动态生成表单，后端不写死表单结构——加一个模板不用改一行前端代码。

### 第三，几个坑，提前想到

- **占位符与 variables 的 key 对不上** → 渲染缺数据。`${变量名}` 与 variables 的 key 必须一一对应。
- **必填项不校验** → 生成残缺稿。渲染前校验 required。
- **停用模板还能用** → 停用后必须不可用于新写作（历史稿件不受影响）。
- **模板不按用户隔离** → 别人能用你的模板。模板带 user_id，查询强制。

## 三、代码怎么写

### 模块分工表

| 类                      | 职责                                              |
| ----------------------- | ------------------------------------------------- |
| `TemplateController`  | 模板 CRUD + 启用停用（writing-api）               |
| `TemplateService`     | 渲染 + 变量填充 + Prompt 组装（writing-business） |
| `TemplateRepository`  | ES 模板索引存取（writing-storage）                |
| `VariableFormBuilder` | 前端根据 variables 动态生成表单（Vue3）           |

### 一个完整模板长这样（周报模板，即 ES 文档内容）

```json
{
  "id": "tpl-weekly-001",
  "user_id": 1,
  "name": "周报模板",
  "description": "标准周报，用于员工每周向直属上级汇报",
  "structure": "请按以下结构生成一份周报：\n标题：${title}\n\n【本周工作】\n${week_work}\n\n【下周计划】\n${next_plan}\n\n【风险与求助】\n${risk}\n",
  "variables": [
    { "key": "title",     "label": "周报标题",   "type": "text",     "required": true },
    { "key": "week_work", "label": "本周工作",   "type": "textarea", "required": true },
    { "key": "next_plan", "label": "下周计划",   "type": "textarea", "required": true },
    { "key": "risk",      "label": "风险与求助", "type": "textarea", "required": false }
  ],
  "prompt": "生成一份语言简洁、条理清晰、面向直属上级汇报的标准周报。",
  "status": "enabled"
}
```

### 主角：TemplateService（渲染，writing-business）

```java
@Service
@RequiredArgsConstructor
public class TemplateService {

    private final TemplateRepository templateRepository;

    public String render(TemplateDoc tpl, Map<String, Object> params) {
        // 1. 校验必填项：遍历 variables，required=true 的 key 必须在 params 里
        for (var v : tpl.getVariables())
            if (Boolean.TRUE.equals(v.isRequired()) && !params.containsKey(v.getKey()))
                throw new BusinessException(ErrorCode.MISSING_REQUIRED_PARAM, v.getKey());

        // 2. 替换 structure 里的 ${变量名}
        String body = tpl.getStructure();
        for (var entry : params.entrySet())
            body = body.replace("${" + entry.getKey() + "}", entry.getValue().toString());

        // 3. 组装模板写作 Prompt：核心记忆身份 + 模板正文 + prompt 规范说明
        return tpl.getPrompt() + "\n\n" + body;
    }
}
```

逐行解析：先校验必填（防残缺稿）；再按 key 替换占位符（key 与 `${}` 一一对应）；最后把 `prompt` 规范说明和填充后的正文拼成给 LLM 的 Prompt。

### 组装后的 Prompt 示意

```
你是一个专业写作助手，负责按模板生成规范文稿。
请按以下结构生成一份周报：
标题：市场部张三 2026年第1周周报

【本周工作】
1. 完成新品上线的市场推广方案
...

生成一份语言简洁、条理清晰、面向直属上级汇报的标准周报。
```

### 配角：前端动态表单（Vue3）

```vue
<template>
  <el-form v-for="v in template.variables" :key="v.key">
    <!-- 按 variables 的 type 生成：text → 输入框；textarea → 多行；select → 下拉；number → 数字 -->
    <el-input  v-if="v.type==='text'"     :placeholder="v.placeholder" v-model="form[v.key]"/>
    <el-input  v-else-if="v.type==='textarea'" type="textarea" v-model="form[v.key]"/>
    <el-select v-else-if="v.type==='select'"   v-model="form[v.key]"/>
  </el-form>
</template>
```

要点：后端不写死表单结构，前端根据 `variables` 动态渲染——模板怎么配，表单就怎么长。

最值钱的回归测试：

```java
@Test
void render_missingRequiredParam_throws() {
    Map<String,Object> params = Map.of("title", "周报");   // 缺 week_work
    assertThrows(BusinessException.class, () -> templateService.render(tpl, params));
    // 不校验 → 生成残缺稿
}

@Test
void render_replacesAllPlaceholders_noResidue() {
    String rendered = templateService.render(tpl, fullParams());
    assertFalse(rendered.contains("${week_work}"));   // 没残留未替换占位符
}
```

## 五、做完怎么验

harness 全绿后，人工确认：

1. 前端新建一个模板（填 structure + variables），选它 → 动态表单正确生成
2. 填参数提交，生成的文稿结构完全符合模板 structure
3. 停用模板后，工作台选不到它；历史稿件不受影响
4. 两个用户的模板互不可见

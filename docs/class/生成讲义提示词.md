# 讲义生成提示词 —— 从 TechnicalSolution 生成"功能原理解析、实现与代码讲解"

> 用途：参照 oryxos `docs/class/` 的课程讲义写法，用一段提示词驱动 AI，把 `docs/TechnicalSolution.md` 的每个功能章节，自动生成一节"原理解析、实现与代码讲解"讲义。
> 每个功能一节，内容严格对齐技术方案的**决策、模块名、表名、约定值**。
> 生成结果存放：`docs/class/第X节：<功能名> 原理解析、实现与代码讲解.md`

---

## 一、oryxos 讲义是怎么写出来的（写作模式）

oryxos `docs/class/` 每节讲义（Provider / ReAct / Memory / Tool / Sandbox / Web Service / 定时任务…）都对应 TechnicalSolution.md 的一个能力，用提示词驱动生成。固定套路是 **五段式 + 口语化 + 图/码/表三件套**：

| 段 | 讲什么 | 对应 TechnicalSolution 哪部分 |
|---|---|---|
| 一、是什么，干嘛用的 | 一句话定义 + 通俗例子 + 背景 | 能力定位 |
| 二、动手前先想清楚 | 职责怎么拆、为什么自己写不用框架、**几个坑提前想到** | 关键技术决策（决策N） |
| 三、代码怎么写 | 模块分工表 → 主角代码骨架 → **逐行解析** → 配角模块 → 编排者 | 模块组成 + 关键设计点 |
| 四、验收 harness | 测试类 → 验收点表格 + **2 个最值钱的回归测试** | 非功能 / 验收标准 |
| 五、做完怎么验 | 人工确认清单 | 实施节奏 / 验收 |

写作风格三要素：
- **口语化讲来龙去脉**：讲清"为什么这么做"，不堆术语、不抄文档
- **mermaid 流程图**：主流程流转图、模块协作图，至少 2 张
- **代码骨架 + 逐行注释 + 模块分工表**：给骨架和逐行解析，不用完整大段代码

## 三、wordpilot 完整示例：素材 RAG 管线（能力二）

````markdown
你是 wordpilot（ScriptAgent 智稿引擎）的资深讲师兼源码作者，精通 Java 21 + Spring Boot 3.x +
AgentScope2.0 + ES7 + ONNX Runtime。把"素材 RAG 管线"写成"一节课"，讲透来龙去脉。

## 输入材料
- 精读 `docs/TechnicalSolution.md` 第 6 章《素材 RAG 管线》整章；相关：决策五（RAG 管线自实现）、
  §9.3 模型选型（Embedding = BGE bge-m3 本地模型 + JVM 进程内 ONNX Runtime 推理，dim 1024）、
  §8.3 ES 操作、流程二（素材上传入库）、流程三（素材仿写）、数据模型 writing_material /
  writing_material_chunk（embedding dense_vector dim=1024、检索 cosine）
- 对齐约束：constitution 原则七（RAG 管线自实现，任一步失败报错回退、删除素材同步清 ES）、
  原则五（检索强制 user_id）；CLAUDE.md 模块 writing-storage（解析/切片/ES）、writing-model（Embedding）

## 产出
一节讲义《第2节：素材 RAG 管线 原理解析、实现与代码讲解》，输出 Markdown，放 docs/class/。

## 固定结构（五段）
一、素材 RAG 是什么，干嘛用的
  一句话：把用户上传的文档切碎转成向量存进 ES，写作时按语义把最相关的片段捞回来喂给大模型。
  通俗例子：你要"照着公司年报风格写周报"，系统先把你之前传的年报切块存好，写的时候把最像年报的
  几段捞出来当参考。在整套系统里它是能力二"素材仿写"的地基。
二、动手前先想清楚几件事
  职责拆分：解析(writing-storage) / 切片(writing-storage) / 向量化(writing-model) /
    ES 入库检索(writing-storage)，一条链各司其职。
  为什么自己写不用现成 RAG 框架：链路每个环节都是成熟组件，但组合逻辑要可控（切片参数、失败回退、
    user_id 隔离、删除清理），自己串更清晰。
  几个坑提前想到：
    · 切片参数写死 → 召回质量没法调，长度/重叠要可配置
    · ES 索引维度与 bge-m3 不一致 → 入库检索报错，dim 必须 1024 + cosine
    · 向量化失败产生半成品 → 任一步失败要回退，不落半截数据
    · 删除素材没清 ES → 孤儿向量数据，按 material_id 同步清理
    · 检索漏 user_id → 越权拿到别人的素材片段，检索强制带 user_id
三、代码怎么写
  模块分工表：DocumentParser（POI/PDFBox→纯文本）、ChunkSplitter（固定长度+重叠，参数配 yml）、
    EmbeddingClient（writing-model，本地 ONNX Runtime 加载 bge-m3，load-on-start 单例）、
    MaterialChunkRepository（ES 批量写入/检索，dim=1024 cosine）
  主角类 DocumentParser / ChunkSplitter 代码骨架 + 逐行解析（文件类型分发、解析、按长度切、
    重叠保留、清空片段）
  配角：EmbeddingClient 加载本地模型、MaterialChunkRepository 的 upsert 和
    `search(userId, queryVector, topK)`（带 user_id 条件）
  编排者：MaterialService（writing-business）把上传→解析→切片→向量化→入库串起来，任一步失败抛错回退
四、验收 harness
  测试类 | 覆盖的验收点 表格：
    DocumentParserTest（docx/pdf/txt/md 四种解析、坏文件报错不落库）
    ChunkSplitterTest（固定长度+重叠切得对、空文档边界）
    MaterialChunkRepositoryTest（ES 写入/检索、检索强制 user_id、删除按 material_id 清干净）
    MaterialServiceTest（上传全链路成功、向量化失败回退不产生半成品）
  最值钱的回归测试（贴代码+注释）：
    · 检索漏 user_id 的回归（不带 user_id 查不到、不会串库）
    · 删除素材后 ES 无残留切片的回归
五、做完怎么验
  harness 全绿后人工确认：传一份真实 docx → 素材列表可见、ES 能搜到该用户的切片、
    换另一个用户检索不到、删除素材后 ES 该 material_id 无残留

## 硬性要求
- 口语化讲清"为什么这么做"，不堆术语
- 至少 2 张 mermaid 流程图（上传入库链路图、素材仿写检索链路图）
- 代码给骨架 + 逐行注释；表格至少 2 张
- 模块名、表名、约定值必须与 TechnicalSolution/constitution 完全一致
- 结尾"本节交付物（Spec-Kit 拆解锚点）：代码/测试/表/约定"
````

## 五、使用方法

1. 选一节功能，从第 4 节清单拿到对应技术方案章节和关键决策
2. 把第 2 节模板复制一份，填好 `{}` 占位（或直接参考第 3 节示例改）
3. 喂给 AI（Claude / 豆包等），让它精读 TechnicalSolution.md 对应章节后产出讲义
4. 生成结果放 `docs/class/第X节：<功能名> 原理解析、实现与代码讲解.md`
5. 抽查对齐：模块名/表名/约定值与 TechnicalSolution/constitution 一致；有 mermaid 图和回归测试

> 版本说明：讲义内容随 TechnicalSolution.md 演进；若技术方案章节/决策有改动，对应讲义需重生成。
